# Noble Stars

Brawl Stars–inspired top-down arena battler (Showdown mode: last fighter standing, shrinking gas ring, loot-box power cubes). **Active development is the 3D Godot 4 game in `godot/`.** The original SpriteKit iOS game (`NobleStars/`) is v1 — complete, kept working, but not being extended.

## Godot 3D game (`godot/`) — main development

Godot 4.7, everything built in code (the `.tscn` files are near-empty shells). Entry scene is `menu.tscn` (Brawl Stars–style lobby, see below); `game.tscn` is the match. Scripts live in `godot/scripts/`: `main.gd` is the match hub (mirrors v1's GameScene), plus `fighter.gd`, `arena.gd`, `bot_brain.gd`, `gas_ring.gd`, `kits.gd` (character data), `projectile.gd`/`lob.gd`, `virtual_joystick.gd`, `super_button.gd`, `session.gd`, `loading_screen.gd` (autoload `Loading`, see **Match bookends**), and for Nobles Cup `cup_mode.gd` (`CupMode`, the rules) + `ball.gd` (`Ball`). Menu system (see **Menu** below): `menu.gd` (`MenuShell` — stage scaling, screen stack, toasts/popups/particles), `menu_stage.gd` (`MenuStage` — the full-stage 3D view: the fighter on the arena's own ground, fading to ink), `scripts/menu/` (the screens), `ui_kit.gd` (the old navy/gold StyleBox helpers, now only `room_screen.gd` uses them), `save_game.gd` (`SaveGame` statics → JSON at `user://save.json`: per-fighter trophies, coins, gems, unlocks, pass progress, settings; Showdown ranks 1–10 award +8,+6,+5,+4,+3,+1,0,0,−1,−2 trophies, `max(2, 22−2·rank)` coins and `max(40, 180−12·rank)` Nobles Pass tokens via `SaveGame.award_match`, called from `main.gd:_end_match`). **Stats come from `kits.gd`, never from `brawlers.json`** — the JSON carries copy, art ids and shop/pass/news config only.

Run it: `/Applications/Godot.app/Contents/MacOS/Godot --path godot` (add `--headless --import` after adding files — REQUIRED after new scripts too, or class members silently vanish at runtime). **Run one Godot at a time on this project.** Two processes contend on the import lock badly enough to look like a hang: an import that normally takes 1.2s sat for six minutes alongside a second instance and finished in 1.9s once it had the project to itself. If a run or an import stalls with no output, check for another `Godot` before debugging anything else. Three things about doing that, each of which has already gone wrong here:

- **Detect with `pgrep -x Godot`, then check each hit's `--path`.** `pgrep -x` matches the binary by exact process name, so unlike `ps -eo command | grep Godot` it never matches the *shell running your own script* (that form reports a held lock forever, including when the lock is free — and the `[G]rep` trick does not save you, it only excludes the grep itself). But `pgrep -x` alone over-matches in the other direction: **another Claude session running `NS3_SIM` on its own scratchpad copy** of the project is a Godot process that holds no lock of yours, and waiting on it stalls indefinitely. This has already cost one session several minutes of dead waiting. Filter the hits:
  ```sh
  ours() { for P in $(pgrep -x Godot); do ps -o args= -p $P 2>/dev/null \
      | grep -qE -- '--path (godot|\.)( |$)|NobleStars/godot' && return 0; done; return 1; }
  until ! ours; do sleep 2; done
  ```
- **Never kill a Godot you have not identified.** A human playing the game looks exactly like a stale agent process except for two tells: its parent is an interactive shell (`-zsh`), not a Claude bash wrapper, and it was launched with an absolute `--path /Users/…/NobleStars/godot`. Agents here use `--path godot` from the repo root or `--path .` from inside it. Killing the wrong one closes the game out from under the person playing it. Wait, or skip the run.
- **Kill the job, not the binary.** `pkill Godot` leaves the shell that launched it alive, and it will start the next Godot in its chain minutes later and retake the lock.

**`--headless --import` is NOT a compile check.** It does not report GDScript parse errors — a `main.gd` that could not load at all imported silently, and the `SCRIPT ERROR: Parse Error` only appeared on running the game. This is a sharp edge precisely because the PostToolUse hook makes the import feel like one. To know a script actually parses, run the game. A **PostToolUse hook in `.claude/settings.json` now runs that reimport automatically** after any edit to a `godot/**/*.gd`, so the footgun is handled for Claude Code edits; you still need it by hand after adding assets outside the editor. `godot/.godot/` is gitignored, so a **fresh clone must import once** (~5s) before the project will open or run.

**Wifi multiplayer** (`net_play.gd` autoload `Net`, `room_screen.gd`, net section at the bottom of `main.gd`): host-authoritative LAN play over ENet (port 42537). The host runs the exact single-player sim (bots fill empty Showdown slots); clients send stick input + fire requests up as RPCs and render 30Hz snapshots (positions/health/ammo/super) plus reliable events (attacks, eliminations, loot boxes, cubes, wall breaks) — `authoritative` in main.gd gates every mutation so client-side projectiles stay visual-only. Rooms: lobby → WIFI MATCH → host or join (UDP broadcast discovery on 42538, join-by-IP fallback — iOS can't receive broadcast replies without Apple's multicast entitlement, so on iPhone use join-by-IP). The host's own death shows results but the match keeps simulating; only the host gets PLAY AGAIN. Client fighters are pure puppets (no prediction) — fine on LAN RTTs.

**Current state:** full Showdown match playable — nine kits (Nova shotgun, Tony lob, Henry melee/dash, Sanjit fast melee/boomerang, Kovacs tank clap/jump-smash, Leon controller buttons/disconnect, Anders hacky-sack control, Hammy heat-streak sniper/bank-shot Super, Ayaan slalom curveballs/steerable Downhill run), bots, gas ring, loot, twin floating touch sticks (move left half, aim right half — release fires, tap auto-aims), drawn Super button, results overlay (awards trophies, coins, and Pass tokens into the save). Desktop fallbacks: WASD, Space auto-aim, E Super. Menu is a game-programme roster page (see **Menu**): the selected fighter's GLB idling center-stage on the arena's own ground fading to ink (capsule fallback), their stat column and ability write-ups filling the flanks, PLAY + mode plate bottom-right, ROSTER/SEASON/SHOP/WIFI as text links bottom-left, identity and currency across the top. Nova is the sole starter; Trophy Road runs 100→5000 trophies and unlocks Sanjit, Tony, Kovacs and Henry by name, alongside coins, gems, Power Points, Bling and Dawg Treats. Two modes launch — Showdown and Nobles Cup (see below); every other event card is still a locked dummy. `Session.mode` + the mode branch at the top of `main.gd:start_match` are where the next one goes in.

**Menu** (`menu.tscn` → `MenuShell`): the native Godot menu, and the only menu. It began as a port of an HTML build (`web-menu/`, since deleted — a browser page cannot go in the iOS app) and was a Brawl Stars lobby clone: profile and season plates top-left, currency pills top-right, two flanking columns of painted icon chips, mode plate and PLAY bottom-right, over a pre-rendered auditorium JPEG. **That was overhauled wholesale.** Copy and config still live in `godot/data/brawlers.json` and `godot/data/game.json`; `include_filter="data/*.json"` in `export_presets.cfg` is what keeps them in the iOS build — without it the menu ships with no data.

- **The reference world is a printed game programme and a gym scoreboard**, not a mobile brawler. That is where every token comes from, and it is worth stating because the individual rules below look arbitrary otherwise: **radius is zero everywhere**, depth is **hairline rules only** (no bevel, no shadow, no gradient — adding one means adding it everywhere, and then this is the old system again), the type scale has a **deliberate hole** in it (utility labels at 17–22, display at 44+, almost nothing between, because filling the middle is what makes a screen read as evenly loud), and gold is the only colour with a job (earned / active / yours). Display type is **Anton**, labels and body are **Barlow Condensed** — one condensed width family; Lilita One and Nunito were the rounded mobile-game pair this replaced and are gone.
- **Five surfaces, down from thirteen.** Home, Roster, Season, Shop, Wifi, plus the settings/profile popups. Deleted outright: News, Club, Inbox, Matchmaking-as-a-screen, the roster grid's detail card, and the storefront half of Shop. They were furniture for a live-service game this is not.
- **Home is also the detail screen** (`home_screen.gd`). The left flank is the selected fighter's identity and stat column, the right is their attack/Super write-ups and record; the middle is the live fighter. **This is what stops the width being dead space** — a single figure centred on a 1920 stage leaves two empty thirds, which is exactly the gap Brawl Stars fills with icon columns, and filling them with the fighter's own data means the width carries content instead of navigation. It gets better as the stage widens on a phone. Because home shows the detail, `RosterScreen` is a plain picker that selects and returns (two taps to change fighter, down from five).
- **Stats print as figures, not tiers.** `MenuData._merge` emits both: `speed`/`range`/`reload` are the tiered labels ("Very Fast"), and `speed_value`/`range_value`/`reload_value` are the raw numbers the flank column prints. A word in a table of numerals breaks the column and says less. Range is in **tiles**, the unit the balance work is done in.
- **There is no background image.** `MenuStage` fills the stage with one 3D view: the arena's own `GROUND_SHADER` on a plane, `Arena.make_sun()`, and depth fog that takes the ground out to `MenuUI.INK` a few metres past the fighter. Two constants are load-bearing and coupled — **`FOG_BEGIN` must stay outside the camera distance** `_frame_camera` computes (~8.6 m), because depth fog does not care that its subject is the point of the picture and will fog the fighter; and **`GROUND_DIM`** exists because the match floor is lit for reading a fight on, and at that exposure it filled the frame and drowned every dim label on the flanks. Pitch markings are off: `pitch_mark` draws the halfway line through the centre spot by definition, so asking it for the centre circle also puts a bright band across the fighter's shins. Deleting the JPEG also deleted the framing chain that existed only to line the 3D fighter's feet up with a painted floor line (`FLOOR_FRAC`, `BRAWLER_VIEW`, `foot_fraction`, `_place_brawler`).
- **`MenuUI.hex()` takes a Color as well as a string.** game.json carries colours as `"#57c81e"`; `kits.gd` carries them as real `Color`s that `MenuData` passes straight through. Round-tripping one through `str()` yields `"(0.2, 0.88, 0.78, 1)"`, which is not a colour name — Godot logged an error per fighter and returned black, which is why the roster's team blocks came out unpainted.
- **Layout is in "stage pixels".** Screens are authored against a 1920×1080 stage; `MenuShell._fit_stage` scales it to the device and *widens* it past 1920 on anything taller than 16:9 (a phone gains stage width instead of black bars), honouring the iOS safe area.
- **Files.** `scripts/menu/`: `menu_data.gd` (JSON + `Kits` merge — copy from the JSON, live balance from `kits.gd`; a kit with no JSON entry, like Nova or Hammy, is synthesised), `menu_ui.gd` (the design system), `menu_screen.gd`/`menu_popup.gd` (screen + popup bases), `menu_audio.gd` (every SFX synthesized at runtime — no SFX files ship), `home_screen.gd`, `roster_screen.gd`, `season_screen.gd`, `shop_screen.gd`, `modes_screen.gd`, `menu_popups.gd` (settings + profile). Every route in is `MenuShell.show_screen(name)`, which keeps the old thirteen-screen names as aliases so a stale hook lands somewhere sensible.
- **Godot layout gotchas this menu hit.** `PanelContainer` stretches *every* child to fill it, so a card with overlays must be `MenuUI.card()` — a plain `Panel` — with `MenuUI.card_body()`. `set_anchors_and_offsets_preset(..., PRESET_MODE_MINSIZE)` reads a minimum size a node does not have until it is in the tree; use `MenuUI.pin()`. A `ScrollContainer` has no minimum height, so a popup built around one collapses to its title bar.
- **Unlocks are real.** `SaveGame.ensure_loaded` seeds only `MenuData.starting_brawlers()` (Nova); everyone else is locked, shows their `unlockHint` in place of their numbers on the roster row, and arrives through a named Trophy Road milestone or a Dawg Treat. **Leon, Anders, Hammy and Ayaan have no named unlock**: the road covers Sanjit, Tony, Kovacs and Henry, so those four are reachable only through a Treat. Settings → Developer mode unlocks everyone on the current save.
- **Season merges Trophy Road and the Pass** (`season_screen.gd`), because they answer the same question and differ only in whether they reset. Road entries are `{trophies, reward: {kind, amount|id}}` (the older flat `{trophies, kind, ...}` is still accepted by `_payload`); Pass claims are keyed `pass:<tier>:<free|premium>`. Kinds: `coins`, `gems`, `power_points`, `bling`, `dawg_treat`, `star_drop`, `skin`, `brawler` (named, by `id`) and `brawler_drop` (random, rarity-weighted, no duplicates). Adding a kind means touching `_reward_name`, `_claim` and `SaveGame.grant` together.
- **Shop is a sink, not a store.** The gem packs priced in dollars, the bundles and the row of tiles reading PURCHASED are gone; what is left is the loop that was already real — `award_match` grants coins, so power levels, Dawg Treats and the resource swaps are where they go. `_affordable_deals` filters `game.json` by currency rather than hardcoding a list, so a dollar-priced item added to the JSON simply will not appear. The Treat's odds are printed from the same `TREAT_TIERS` that `_roll_tier` runs on.
- **Wifi play** is a link on the home bar (WIFI), which opens the old `room_screen.gd` unchanged. `room_screen.gd` and `ui_kit.gd` are the one corner the overhaul did not touch.
- **`godot/assets/menu/` went from 124 files to 34.** What remains is what is still referenced: three fonts, `portraits/` (used by the versus screen, the results card and the loading screen — *not* by the menu), `svg/`, `audio/` (three MP3s: lobby music, the versus sting, the battle track) and `background/loading_keyart.jpg`. `bg.png`, the `btn_*` chips, `icons/`, `cards/`, `treats/`, `decor/` and `pack/` were all deleted with the screens that used them.

**Nobles Cup** (`cup_mode.gd`, `ball.gd`, `Arena.PITCH_MAP`) — the Brawl Ball mode, 3v3, first to two goals or ahead when the 2:30 clock runs out. Menu id `nobles_cup` → engine mode `"cup"`; `NS3_MODE=cup` alongside `NS3_KIT` drops straight into one.

- **Everything mode-specific is in `cup_mode.gd`**, which main.gd calls at four points: `build_match`, `tick`, `on_death` and `frozen` (the last holds input through a kickoff and after the whistle). Showdown's match loop is otherwise untouched, and `cup == null` is the guard on every branch.
- **Teams are real.** `Fighter.team` is 0/1 (−1 = Showdown free-for-all, where `is_ally` is false for everyone). `deal_damage` and `nearest_visible_enemy` both check it, so friendly fire and friendly targeting are off everywhere at once. Team is worn as a coloured ground ring — it can't tint the body, because five kits wear a GLB whose materials are the character's. Health bars go green for your side and red for theirs (`fighter_bars.gd`); Showdown keeps kit colours.
- **Death is a setback, not an exit.** `_eliminate` hands off to `CupMode.on_death`, which parks the fighter (`Fighter.knock_out`) and books a respawn three seconds later; `fighters` never shrinks, and everything that walks it already skipped `is_dead()`. Overtime is sudden death and books nothing.
- **You respawn inside your own goal**, not at the kickoff spot — a body in the mouth is where the mode's defending comes from. There is deliberately no goalkeeper bot; an early build had one and it was strictly worse than the wall. Kickoff spawns are on the middle third, two tiles apart, so the whole team is on screen at the start.
- **The pitch does the defending.** 15x23 tiles, mirrored on both axes (every row is a palindrome — keep it that way). A solid five-tile breakable wall sits two tiles off each goal, so nothing can be shot at the mouth from beyond it and the attack has to come round the outside. Overtime levels every breakable wall, that one included, which is what opens the goals up. Only the `=` goal frame survives. Both teams spawn on the middle third, so a kickoff is a race.
- **The ball is not a physics body.** It reflects off `Arena.blocks_movement` per axis, so bounces are exact and reproducible; a RigidBody3D would creep into wall seams and squeeze the posts. It is caught by anyone it rolls within `PICKUP_RADIUS` of, which is what makes interception work.
- **The carrier can't attack at all, only kick.** A normal kick spends an ammo bar and obeys the same attack cooldown as a shot, as it does in Brawl Ball, so the ball cannot be machine-gunned up the pitch and running dry is a real reason to hold on to it. It runs ~7 m (3.5 tiles), deliberately inside the 5.5-tile weapon range cap — a kick is a pass, not a shot from anywhere. Spending the Super on the ball is the **Super Shot**: `Ball.SUPER_KICK_MULT` doubles the launch speed, and because drag is constant that doubles the distance too (~15 m), matching Brawl Ball's "shoots it further and faster, but uses up the Super". It costs the Super and no ammo, so it is also the carrier's out when the magazine is empty. While carrying, the Super never fires the kit's Super, and an uncharged one is swallowed rather than falling through to an attack. Every player attack funnels through `main.gd:_fire_player`, which is the backstop; `_release_fire`/`_auto_aim_fire` resolve the aim first (drag aims, tap uses `CupMode.kick_aim`, which shoots inside `SHOT_RANGE` — doubled for a Super Shot — and otherwise passes). The aim indicator switches to the ball's own path, bounces and all, via `_aim_bounce_segments(..., decay)`; the Super Shot's lane is gold and twice as long.
- **The ball is dropped by a dash, a leap or a real knock** (`CupMode.KNOCK_DROP_SPEED`, above every melee lunge and below the knockback Supers deal), on top of death. Brawl Ball's own rule is stun/knockback/defeat; dashes and jump-smashes are added because otherwise every mobility Super is a free run at the goal.
- **Bots route around the goal wall** rather than into it. `Arena.route_to_goal` is a BFS distance field per goal, rebuilt only when a wall opens, with a five-tile lookahead so the run is a curve and not a corner-hug. Steering straight at the mouth parked carriers against the wall until someone took the ball off them; measured after the fix, carriers deviate >40° from the straight line exactly at 6-9 m out, which is where the wall is.
- **A destroyed wall leaves the ASCII map** via `Arena.open_at`, called from the projectile hit, the net RPC and overtime. Bot movement, route finding and the ball's bounces all read `Arena.rows`, so a wall only freed from the scene keeps blocking every one of them — overtime would otherwise leave the ball rebounding off gaps you can see through. This applies to Showdown too, where bots previously kept pathing around walls that were no longer there.
- **Pacing lives in four constants.** `Ball.KICK_SPEED`/`DRAG` (deliberately slow — a fast ball made every shot on target a goal and ran a match out in 13 seconds), `Ball.SUPER_KICK_MULT`, `CupMode.SHOT_RANGE`, and the goal wall. Retune those before touching anything else, and re-measure with a batch of headless matches rather than one — variance between single matches is large.
- **Not wired for wifi play.** `net_play.gd` and the whole net section of main.gd are Showdown-only; hosting a Cup match would need the ball, score and respawns added to the snapshot.

**Bushes** (`arena.gd`, the block under `GRASS_MODEL`): each `b` tile gets two MultiMesh instances — a flat **skirt** quad sized exactly to `Kits.TILE` and a `tall_grass.glb` **canopy** on top. The skirt is what makes a bush read as a *tile*: adjacent quads meet with no seam, so a patch becomes one contiguous dark shape, and its outline is merge-aware (`_open_edges` packs "this side has no bush neighbour" into `INSTANCE_CUSTOM`; the shader rims only those sides, so a 3x3 patch is one shape and not nine squares). The canopy has no yaw/scale jitter on purpose — the old jitter existed to stop a field reading as tiled, which is now exactly the goal. Both layers fade any instance within `Kits.BUSH_REVEAL` of `reveal_center`, which `main.gd:_update_concealment` points at the player every physics frame, so the concealment radius `can_see()` enforces is the same one you can see through. Two gotchas: both layers are transparent and never get a depth sort, which works only because `_build` appends bushes row-major from the map's -Z edge (the far side of a camera at +Z) — that buffer order *is* the painter's order; and the skirt carries `render_priority = -1` so it never flips in front of its own canopy.

**Match bookends** (`loading_screen.gd` autoload `Loading`, `versus_screen.gd`, and the results half of `main.gd`) — what wraps a match at both ends.

- **Entering and leaving a match go through `Loading`,** never `change_scene_to_file` directly. It is an autoload precisely so it outlives the swap it is covering: a loading screen owned by the scene being replaced dies halfway through the job. `Loading.to_match(get_tree())` (from `menu.gd:start_match`) and `Loading.to_menu(get_tree())` (LOBBY, and a lost host) threaded-load the target scene **plus every character GLB**, keep a reference to each in `_held` for the life of the session — which is what makes `fighter.gd`'s later `load(kit.model)` a cache hit instead of a disk read on the frame a fighter spawns — and only lift once the incoming scene calls `Loading.done()`. That call is at the **end of `start_match()`**, not in `_ready`: `start_match` awaits a frame partway through, so `_ready` returns before the arena exists. `MIN_SHOW` keeps the screen up long enough to read as a transition rather than a flash, and `SAFETY_SECONDS` lifts it anyway if a path forgets to call `done()`. The `NS3_*` hooks that skip the menu deliberately keep the old direct scene change, so the sim and screenshot harnesses are untouched.
- **`ResourceLoader.load_threaded_get` CONSUMES the request.** Poll a path again after collecting it and `load_threaded_get_status` reports `THREAD_LOAD_INVALID_RESOURCE` — so a naive "re-check everything each frame" loop sees every *finished* load as a *failed* one. Collect each path once and drop it from the pending list.
- **Per-match stats are on the fighter** (`Fighter.stats`: damage, kills, cubes, goals, saves, survived). Always on, and distinct from `main.gd`'s `sim_stats`, which is a per-KIT aggregate gated behind `sim_active` and answers a different question. Nothing in `stats` is cleared by `respawn()` — a Nobles Cup death is a setback inside one match, so a carrier who scores and then dies keeps the goal. `survived` measures from `match_start` (set when the phase turns PLAYING), not from `now`, which runs for the life of the scene and would otherwise report the second match after PLAY AGAIN as the sum of both.
- **All three ways a match can end funnel through `main.gd:_show_results`** — Showdown placement, a Cup scoreline, and a net client whose own fighter went down while the host's match ran on — so they cannot drift apart. It builds a `MenuUI` card fresh each time into `results_body`; only the overlay root and its dim persist. Its optional `board` argument swaps the portrait-plus-stat-table body for a prebuilt one: Cup passes `_cup_scoreboard` (both teams, all six players, sorted goals-then-damage), Showdown and the net client pass nothing. Two details are load-bearing — `hud.move_child(results, -1)`, because the fighter health bars are added to the HUD *after* the overlay is built in `_ready`; and hiding `CupMode.HUD_GROUP`, because Cup's scoreboard sits on its own layer *above* the card, where `move_child` cannot reach it and the scoreline printed twice. Hidden rather than freed — `CupMode._build_hud` sweeps it on PLAY AGAIN.
- **A per-player table is possible in Cup and not in Showdown.** `game.fighters` never shrinks in Cup — a death parks a fighter rather than freeing it — so everyone is still there at the whistle with their stats intact. Showdown frees them on elimination, so by the results screen most of the roster is gone.
- **A net client's stat table is one row.** Every mutation is host-side (`deal_damage` returns early when `not authoritative`), so a client's `stats` are all zeros; `_net_rows` shows only the clock it keeps itself rather than a column of noughts.
- **The versus screen already animates** (cards slide and stagger, VS punches in with `TRANS_BACK`, the countdown digits scale, the mode title takes over at `PREMATCH_INTRO_AT`). It landed in `d4e6678`; do not "add" it again.

**Match feel** — the effects layer, and the two rules it follows.

- **Effects are ImmediateMesh, not GPUParticles3D.** `shockwave.gd`, `melee_swipe.gd` and `hit_spark.gd` all rebuild a mesh per frame from vertex colours, unshaded, and free themselves. The camera is a fixed steep top-down, so a spray drawn flat in XZ reads from the only angle anyone sees, costs one draw call, and ships no art file — the same reasoning that makes every sound synthesized.
- **Two things will make a new effect invisible while rendering perfectly.** It needs `no_depth_test` if it sits on a fighter (a burst at chest height is hidden by that fighter's own body at a 60° camera pitch), and it needs to be **big**: the camera shows ~23 m across 1280 px, about 55 px/m, and a fighter is only ~70 px wide, so sub-metre geometry is a handful of pixels. `HitSpark`'s first pass at 1.5 m with darts spanning half of that was measurably spawning and completely unseeable.
- **A brief effect cannot be tuned from a screenshot.** Five frames is nothing. Hold it open — set the duration to ~1.5s temporarily, shoot it, then put it back. The same trick is how `Fighter.FLASH_ENERGY` was set.
- **Per-fighter visual state must not touch the GLB's own materials.** They live on a Mesh *resource* shared by every fighter wearing that model, so `_setup_model` duplicates each surface material and installs it as a surface override; the hit flash and bush fade drive those copies. The flash is **emission**, since `albedo_color` multiplies the texture and white is a no-op on a textured character. `set_concealed` runs every physics frame for every fighter and switching a transparency mode recompiles a shader, so `Fighter._conceal_applied` gates it to real transitions.
- **`main.gd:clear_in_flight()`** frees everything a weapon has put in the air (and `DisconnectZone`/`Shockwave`/`MeleeSwipe`), shared by `start_match` and `CupMode.kickoff` so the lists cannot drift. It deliberately excludes the Ball, which a kickoff re-places. Freeing a `Boomerang` is also what returns Sanjit's staff (`boomerang.gd:_exit_tree`).
- **`main.gd:focus_camera(at, seconds)`** points the camera somewhere other than the player for a beat, on a slower lerp than the player follow. Cup uses it on a goal, inside the kickoff freeze that already holds input.

**Debug env hooks** (mirror the v1 ones): `NS3_KIT=nova|tony|henry|sanjit|kovacs|leon|anders|hammy|ayaan`, `NS3_AUTOFIRE=<sec>`, `NS3_AUTOWALK="x,z"`, `NS3_GODMODE=1`, `NS3_SUPER=1` (start with Super charged), `NS3_CUBES=<n>` (start carrying n power cubes), `NS3_SHOTS="prefix:t1,t2,..."` (match-time screenshots, then quits; **give an absolute prefix** — a relative one now lands in `user://` rather than writing into the project, where the next import used to sweep it up as a game asset, and either way the path it wrote is printed), `NS3_END=<sec>` (end the match this long after FIGHT!, with whatever placement the player has by then — the results card is otherwise only reachable by surviving or dying at an unpredictable moment, which made it the one screen `NS3_SHOTS` could not catch; pair them, remembering `NS3_SHOTS` times include the 7s `PREMATCH`), `NS3_MENU_SHOT=<path.png>` (menu screenshot, then quits; combine with `NS3_MENU_SCREEN=lobby|roster|modes|shop|season|wifi|settings|profile|loading` — the old `brawlers`/`fighters`, `pass`, `road`, `friends` and `events` all still resolve as aliases; `loading` is not a screen in the stack but the transition out of the menu, so it presses PLAY and shoots inside `LoadingScreen.MIN_SHOW` — and `NS3_MENU_DETAIL=<kit>`, which now *selects* that fighter, since home's flanks are the detail view), `NS3_MODE=showdown|cup` (which mode to drop into; needs one of the menu-skipping hooks alongside it, and also works when `game.tscn` is run directly), `NS3_RESET_SAVE=1` (delete the save, start fresh), `NS3_SIM=<n>` (balance sim: n all-bot matches at 10x speed, per-kit win/placement/damage table to stdout, then quits — run with `--headless`; the table's `hits/atk` column should sit near a kit's projectile count, and anything near zero means shots aren't landing, which is a delivery bug rather than a balance one — see `CHARACTER_BUILDING.md`), `NS3_SIM_SPEED=<n>` (override the sim's 10x time scale; re-run at 2 to tell physics artifacts from real balance), `NS3_SFX_LOG=1` (print every match sound as it fires, with its distance from the listener — synthesized audio is easy to mis-hear as missing when it is only quiet, so this is how you tell "the hook never ran" from "turn it up"), `NS3_SAVE_LOG=1` (Nobles Cup: print every loose-ball pickup with the pace, the angle to the catcher's own goal and whether an opponent touched it last — how the results card's SAVES row is tuned, and how you tell "the rule never matched" from "the situation never arose"), `NS3_BOT_LOG=1` (print every time a bot takes cover, settles into a bush or holds an ambush — terrain use is rare enough per bot to look absent when it is only occasional, so this is the same "did the rule match" instrument as `NS3_SAVE_LOG`; a run that prints `wanted cover and found none` in bulk means the scan is firing where no wall can help). NS3_KIT/NS3_AUTOFIRE/NS3_SIM skip the menu. Net hooks (beat the single-player hooks): `NS3_HOST=<n>` hosts and auto-starts once n players are in the room, `NS3_JOIN=<ip>` joins — two windowed instances with `NS3_JOIN=127.0.0.1` + `NS3_SHOTS` on each is the wifi-play test harness. These are the testing strategy — there are no unit tests.

**GDScript gotchas:** `:=` cannot infer types from ternaries or cross-script members — annotate; never `class_name` anything Godot ships natively (a native `VirtualJoystick` silently shadowed ours — members vanish with only runtime "invalid access" errors; ours is `TouchStick`).

**Godot gotchas beyond GDScript itself:** a **1-pixel-wide `ImageTexture`** in a `TextureRect` (`EXPAND_IGNORE_SIZE` + `STRETCH_SCALE`) drew nothing at all, with no error — `GradientTexture2D` is the working way to lay a gradient scrim over art, and it is less code. Driving a Control's own `size` from its `resized` signal **recurses** and trips a `_set_size` error, so a rotated banner cannot size itself off its parent that way.

**Character model pipeline:** Meshy exports GLB — always run `python3 Tools/fix_meshy_glb.py <file.glb>` on a fresh export before committing (fixes broken material export, +Z facing, and adds the missing Idle clip); cleaned models live in `Assets/3D/` (see its README) and get copied into `godot/assets/` when wired into a kit. A model whose fighter throws what it holds (Sanjit's staff) is re-exported with `--split-held-item left|right`, which carves the item into a `held_item` node; `fighter.gd:set_held_item_visible` hides it while the thrown copy flies and `boomerang.gd:_exit_tree` puts it back. Meshy's run/attack clips drop the hips below the rest pose, so `fighter.gd` calibrates each model's idle foot height at spawn and lifts the model per-frame by however far the lowest foot bone sinks below it; `Godot --path godot --headless --script res://tools/foot_probe.gd` prints the per-clip sink and lift for every model.

**Power-cube performance:** `main.gd` must keep `power_cube.glb` preloaded. Loading the 21 MB source scene inside `_spawn_cube` puts disk/texture work on the loot box's fatal-hit frame and causes a visible freeze. The extracted 4096×4096 base-color and metallic/roughness textures are intentionally capped at 512 via their `.png.import` files (about 582 KB imported total instead of 16.6 MB); preserve that cap and reimport after changing either texture.

**iOS export** (`godot/export_presets.cfg`, templates installed at `~/Library/Application Support/Godot/export_templates/4.7.2.stable/`): `--export-debug "iOS" build/ios/noblestars3d.ipa` writes an Xcode project (export_project_only). Gotchas learned the hard way: iOS export REQUIRES `rendering/textures/vram_compression/import_etc2_astc=true` in project.godot — without it validation fails with an EMPTY error message; Godot's `targeted_device_family` enum is 0=iPhone 1=iPad 2=both (not Apple's); the generated pbxproj contains six unreplaced `$additional_pbx_*`/`$pbx_embeded_frameworks` placeholder lines that must be deleted before xcodebuild will parse it. **Simulator builds are blocked upstream**: godotengine/godot#118161 — 4.6.2+ templates ship simulator libgodot.a as x86_64-only and Xcode 26 has no Rosetta simulators; test on a real device (arm64 device slice is fine) until fixed templates ship.

## v1 SpriteKit game (`NobleStars/`) — complete, maintenance only

SpriteKit + SwiftUI shell, Swift, no external dependencies. Landscape-only, iPhone-only (iPadOS 26 has orientation-lock regressions). All 2D art is generated by `Tools/generate_sprites.swift`. Arena maps are ASCII grids in `ArenaMap.swift` (`#` wall, `b` bush, `~` water, `S` spawn, `X` loot box); 2.5D depth comes from y-sorted `zPosition` (`ZLayer` in `Constants.swift`, which also holds the `PhysicsCategory` bitmasks).

Build & run — full Xcode lives at /Applications/Xcode.app but `xcode-select` points at CommandLineTools, so always prefix builds with `DEVELOPER_DIR`:

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
xcodegen generate          # only needed after adding/removing files or editing project.yml
xcodebuild -project NobleStars.xcodeproj -scheme NobleStars \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
APP=$(find ~/Library/Developer/Xcode/DerivedData -maxdepth 5 -name "NobleStars.app" -path "*Debug-iphonesimulator*" | head -1)
xcrun simctl install <UDID> "$APP" && xcrun simctl launch <UDID> com.ryder.noblestars
```

The Xcode project is generated — never edit `NobleStars.xcodeproj` by hand; edit `project.yml` and re-run `xcodegen generate`.

Gotchas:
- **Simulator screenshots are captured in portrait framebuffer orientation.** The app runs landscape, so `xcrun simctl io <UDID> screenshot x.png` needs `sips --rotate 270 x.png --out x_r.png` before viewing. Don't mistake the raw portrait capture for a broken orientation lock.
- **Debug env hooks** (via `SIMCTL_CHILD_` prefix on `simctl launch`): `NS_KIT=nova|tony|henry`, `NS_AUTOFIRE=<sec>`, `NS_AUTOWALK="dx,dy"`, `NS_GODMODE=1`, `NS_DEBUG_HUD=1`. Any of NS_KIT/NS_AUTOFIRE/NS_AUTOWALK skips the menu. All in GameScene.swift / GameView.swift.
- The simulator can shut down between Bash invocations when Simulator.app isn't open — `open -a Simulator` keeps it alive, or re-boot with `xcrun simctl boot <UDID>`.
- zsh does not glob-expand unquoted variables — resolve the DerivedData app path with `find`, not a wildcard in a variable.
